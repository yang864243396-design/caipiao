# 全彩种连续期下注与开发者诊断设计

## 背景

当前正式方案在上一笔第三方注单仍为 `pending` 时，会被全局门禁阻止进入下一期下注。第三方派奖同步按周期轮询，结算延迟可能超过彩种期长，因此方案会跨过多个开放期后才再次下注。

业务要求适用于所有彩种：运行中的方案不能因为上一笔注单尚未完成第三方结算而跳过下一期。下一期下注必须使用上一期的开奖结果；第三方资金结算与方案下一期下注相互独立。

## 行为规则

1. 每个运行方案对每个第三方开放期最多下注一次。
2. 上一期注单仍在第三方结算中，不阻塞下一期下注。
3. 当前期下注必须使用紧邻的上一期开奖结果计算选号、方向、输赢状态和倍投状态。
4. 不允许使用更早期的开奖结果替代缺失的上一期开奖结果。
5. 上期开奖结果尚未到达时，在当前期可投注窗口内持续重试。
6. 当前期封盘前仍未取得上一期开奖结果时，跳过当前期并写入开发者诊断记录。
7. 第三方资金结算只更新订单状态、返奖金额和资金统计，不重复推进已经由开奖结果推进过的方案状态。
8. 第三方实际接单期号与目标期号不一致时，以第三方返回期号保存真实订单，并写入错期诊断；该实际期号必须参与防重，禁止同一方案再次投注该期。
9. 方案首次开启仍按现有规则跳过开启瞬间所在期，从下一完整期开始运行。

## 状态解耦

### 开奖驱动的方案状态

新增独立的“开奖状态推进”步骤。进入当前开放期前，Worker 查找上一开放期的开奖结果及该方案上一期投注内容，并通过现有玩法计算引擎得到命中结果。该步骤负责更新：

- 当前轮次和倍投索引；
- 当前选号、换号索引和正反投方向；
- 依赖上一期开奖结果的冷热、开某投某等运行状态；
- 已处理开奖结果游标。

开奖状态推进按“方案实例 + 上一期号”保证幂等。Worker 重试、服务重启或多个 Worker 同时处理时，同一期结果只能推进一次。

### 第三方资金结算

第三方派奖同步继续负责：

- 注单状态 `pending` 到 `hit` 或 `miss`；
- 第三方返奖金额、实际盈亏和资金流水；
- 方案累计投注流水、实际盈亏、止盈和止损检查。

派奖同步不得再次修改轮次、选号、换号索引或方向，避免同一期开奖结果被推进两次。若本地开奖结果计算与第三方最终结算结果不一致，保留第三方资金结果，并写入开发者诊断记录；已经发生的后续投注不做追溯修改。

## 当前期下注流程

对每个运行方案和当前第三方开放期执行：

1. 读取当前开放期号并获取其紧邻上一期号。
2. 检查当前期是否已有本地占位记录或第三方已接单记录；存在则直接结束，防止重复下注。
3. 检查上一期开奖结果是否已进入本地开奖表。
4. 如果结果缺失，在当前可投注窗口内保留方案运行状态并等待下一次 Worker 重试。
5. 如果结果存在，在事务内按上一期号幂等推进方案运行状态。
6. 使用推进后的选号、方向和倍数生成当前期投注内容。
7. 创建当前期防重占位并向第三方下单。
8. 保存第三方注单编号、实际接单期号、实际金额和待结算状态。
9. 第三方派奖任务异步更新资金结果，不阻塞下一开放期。

对不依赖上一期开奖结果的固定选号模式，也统一要求上一期开奖结果存在后再进入下一期，以保证所有运行模式的期号节奏一致。

## 并发与防重

- 保留本地“方案实例 + 本地目标期号”唯一约束。
- 增加“方案实例 + 有效第三方期号”防重能力；有效期号优先使用第三方返回的 `third_party_period`，否则使用本地目标期号。
- 开奖状态推进增加独立游标或处理记录，不能继续复用含义混杂的 `last_settled_issue`。
- 下单前锁定方案实例，并在同一事务中完成开奖状态推进检查和当前期占位。
- 第三方已经接单但本地事务失败时，继续使用第三方注单编号回查并幂等补齐，不重复发起下注。

## 开发者诊断

不增加客户端或管理端展示。异常同时写入结构化后端日志和持久化诊断表，便于服务重启、日志轮转后继续按方案 ID 查询。

每条记录至少包含：

- 方案实例 ID、方案定义 ID、会员 ID、彩种；
- 目标期号、上一期号、第三方实际接单期号；
- 异常代码、责任层级、处理阶段、详细错误；
- 上期开奖结果是否已接收、是否已入库；
- 上一笔第三方订单是否已结算；
- 首次发生时间、最后发生时间和重复次数。

异常代码：

- `third_party_draw_missing`：第三方开奖源直到封盘仍未提供上一期开奖结果。
- `platform_draw_sync_failed`：平台已接收到开奖结果，但入库或读取失败。
- `platform_state_advance_failed`：平台计算命中、选号或倍投状态推进失败。
- `third_party_settlement_pending`：第三方注单结算延迟；仅作为状态信息，不得成为跳期原因。
- `third_party_place_rejected`：第三方封盘、限流或业务拒单。
- `third_party_period_rollover`：第三方实际接单期号与平台目标期号不同。
- `platform_place_persist_failed`：第三方已接单，但平台保存或关联订单失败。

同一方案、目标期号和异常代码重复出现时更新最后发生时间与次数，不重复插入大量记录。诊断命令支持按方案 ID 查询最近记录，并明确输出“第三方”或“平台”责任层级。

封盘后发现本地缺少上一期开奖结果时，诊断流程必须再直接查询一次第三方开奖接口：第三方接口同样没有该期结果时归类为 `third_party_draw_missing`；第三方接口已有结果而本地开奖表没有时归类为 `platform_draw_sync_failed`。直接查询本身超时或网络失败时记录原始网络错误，并归类为第三方链路不可用，不得笼统写成“未结算”。上一笔注单的结算状态作为诊断上下文一并保存，但不作为本期未下注的原因。

## 封盘与不可达保证

平台可以消除由待结算门禁造成的跳期，但以下外部条件无法由平台保证连续下注：

- 上期开奖结果在当前期封盘前始终未由第三方提供；
- 第三方下单接口不可用、限流、拒单或在请求期间切换到下一期；
- 网络中断导致当前期内无法确认第三方是否接单。

这些情况禁止使用旧开奖结果补投，也禁止把当前期订单伪装成下一期订单；必须记录准确诊断信息。平台恢复后从下一个满足“上一期开奖结果已到达”的完整开放期继续运行。

## 测试范围

### Worker 回归测试

- 上一期第三方注单仍为 `pending`，但上一期开奖结果已到：当前期正常下注。
- 上期开奖结果已到：使用该结果推进选号和倍投后下注。
- 上期开奖结果未到但尚未封盘：不下注、不暂停，下一次 tick 重试。
- 上期开奖结果直到封盘仍未到：跳过且仅产生一条 `third_party_draw_missing` 诊断。
- 结果已收到但本地读取或推进失败：记录平台责任诊断。
- 同一当前期多次 tick 或多 Worker 并发：最多产生一笔下注。
- 第三方实际接单期号发生切换：保存真实期号、记录错期并防止重复下注。
- 服务在第三方接单后、本地事务提交前退出：重启后回查补齐，不重复扣款。

### 结算回归测试

- 多笔未结算订单可以同时存在。
- 第三方订单乱序结算时，资金记录分别正确更新。
- 派奖同步不重复推进方案选号、轮次和倍投状态。
- 本地命中判断与第三方结算不一致时，资金以第三方为准并产生诊断。
- 止盈和止损使用已确认的第三方资金结果；达到条件后停止未来下注，不撤销已经接单的订单。

### 彩种覆盖

测试通过全彩种共用 Worker 路径覆盖时时彩、六合彩及其他已接入第三方的彩种，并增加波场 3 秒彩的短周期压力用例。实现中不允许按彩种名称增加仅对某个彩种生效的待结算例外。

## 验收标准

1. 任一彩种的上一笔订单处于第三方 `pending` 时，只要上一期开奖结果存在，下一开放期仍能产生一笔正确订单。
2. 连续开放期内，同一方案不会因平台待结算门禁造成缺期，也不会在同一期重复下注。
3. 每笔下注使用紧邻上一期的开奖结果及其推进后的方案状态。
4. 上期开奖结果缺失或任一处理层失败时，开发者能按方案 ID 查到目标期号、卡点、责任层级和详细原因。
5. 用户端不新增任何诊断展示。
